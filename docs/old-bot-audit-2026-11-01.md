# Аудит старого бота на Railway — 2026-11-01

## Що знайшли
- Код: GitHub `retrograd361/kirpich-bot` (публічний), гілка `main`, автодеплой на Railway.
  Один файл `bot.py`, aiogram 3.13 — **бот уже асинхронний**, а не синхронний, як вважалось.
- Railway-акаунт на **Trial**: лишилось ~18 днів або $3.81 кредиту.
- **Той самий репозиторій задеплоєний двічі**: проєкти `discerning-sparkle` і `kind-education`,
  обидва ACTIVE, з однаковим останнім комітом і тим самим ботом.
- У логах `kind-education` безперервно (868+ спроб поспіль):
  `TelegramConflictError: Conflict: terminated by other getUpdates request; make sure that only one bot instance is running`.
- Змінні: BOT_TOKEN + 5 URL (Donatello, Instagram, Monobank, Telegram, TikTok). **Бази даних немає**,
  юзери ніде не зберігаються.

## Чому «в когось працює, в когось ні»
1. **Дві копії бота з одним токеном.** Telegram віддає оновлення лише одному з'єднанню.
   Копії перебивають одна одну, а після кожного конфлікту aiogram чекає ~5 с.
   Через це бот відповідає з затримками і нестабільно.
2. **Заявки в канал:** старий код чекає 10 с, схвалює заявку і ПОТІМ пише людині.
   Після схвалення Telegram уже не дозволяє писати тим, хто не натискав /start, тому
   більшість нових підписників привітання не отримує.

## Що з цього випливає
- Переносити з бази нічого: бази немає. Частину юзерів теоретично можна відновити з логів
  (старий бот логує `Новий користувач: @username (id=...)`), але логи Railway зберігаються недовго.
- Для нового бота: лишити ОДИН сервіс, додати Postgres, вимкнути/видалити другий проєкт.
- Railway прибрав config-as-code для нових сервісів → у новому боті `railway.json` замінено на `Procfile`.
