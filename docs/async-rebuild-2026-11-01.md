# Перезбірка бота Кірпіча на асинхронний стек — 2026-11-01

## Проблема
Старий бот написаний синхронно (Python). Коли багато людей одночасно тиснуть /start,
бот обробляє їх по черзі: поки один запит чекає відповіді від Telegram, інші стоять у черзі,
частина таймаутиться — «в когось працює, в когось ні».

## Рішення
Переписати з нуля на **aiogram 3** (асинхронний фреймворк) + **SQLAlchemy async**.
Асинхронність = поки один запит чекає мережу, бот уже обробляє наступний.
Сотні одночасних /start обробляються паралельно.

## Функції
1. **Хаб-меню** (/start): привітання, номер картки (копіюється кнопкою), кнопки:
   Kick, TikTok, Instagram, Telegram-канал, Donatello, Монобанка.
2. **Автоприйом заявок** у закритий ТГ-канал (chat_join_request):
   бот спершу пише людині в особисті (вітання + меню) — так вона потрапляє в базу,
   потім схвалює заявку.
3. **База юзерів** — усі, хто натискав /start або подавав заявку в канал.
4. **/admin** (тільки для юзернеймів з `ADMIN_USERNAMES`):
   - 🔴 Стрім почався → Kick / TikTok / обидва → картинка → текст (або шаблон) → превʼю → розсилка;
   - 📢 Пост → будь-яке повідомлення (фото/відео/текст) → кнопки-посилання (опційно) → превʼю → розсилка;
   - 🔗 Налаштування → змінити посилання, картку, текст привітання, фото привітання;
   - 📊 Статистика.
5. **Розсилка** у фоні з лімітом ~25 повідомлень/сек (ліміт Telegram ~30/сек),
   обробка RetryAfter, позначення тих, хто заблокував бота.

## Рішення по архітектурі
- `DATABASE_URL` — одна змінна: SQLite локально, Postgres на Railway/Neon. Код однаковий.
- Посилання/тексти зберігаються в БД (таблиця settings) з дефолтами в коді →
  адмін міняє без редеплою.
- Модульно: кожна функція — окремий router у `bot/handlers/`. Нова кнопка в меню —
  один рядок у `bot/content.py`.

## Відкриті питання
- Хостинг: Railway Hobby ($5, Postgres входить у кредит) vs безкоштовні варіанти — вирішує користувач.
- Юзернейми адмінів — друг впише в `.env`.
- Старий бот треба вимкнути перед запуском нового (один токен = один процес polling).

## Результат
- Усе з плану зроблено. Гілка `feature/async-bot`.
- Додатково проти плану: кнопка «Скопіювати номер картки» (copy_text), кольорові кнопки,
  «👀 Як бачать підписники» в адмінці, `/cancel`.
- Важливий нюанс заявок: бот може написати людині ТІЛЬКИ до схвалення заявки,
  тому спершу шлемо меню, потім approve.
- Перевірка: `tests/smoke_test.py` (фейковий Telegram з затримкою 50 мс) — 22/22 на SQLite
  і на Postgres 16. 300 одночасних /start: ~0.5 с (Postgres) замість ~30 с по черзі.
- Не перевірено: живий Telegram (немає токена), перенос юзерів зі старого бота.
